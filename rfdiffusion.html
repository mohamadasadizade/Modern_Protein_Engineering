COURSE / 03 RFDIFFUSION
PART 03 · GENERATIVE PROTEIN DESIGN

De novo protein
binder design

A practical workflow for designing candidate binders against the L1 region of the human insulin receptor using RFdiffusion3.

1. Protein-binding sites and interface residues

Protein binders recognize a specific surface on a target protein. In this workflow, selected target residues act as hotspots that guide the placement and orientation of a newly generated binder.

Important

Hotspot conditioning guides computational design; it does not prove that a candidate will bind or change receptor activity.

2. How diffusion models generate protein backbones

RFdiffusion3 iteratively refines a noisy structural representation into a candidate protein structure while following the supplied target and design constraints.

Target structure + hotspot constraints
↓
Initial noisy representation
↓
Iterative denoising by RFdiffusion3
↓
Candidate binder structure

The output is a computational candidate. Experimental binding and functional assays are required to establish biological activity.

3. Design target: human insulin receptor (INSR)

Our target is the L1 domain region of the human insulin receptor extracellular domain. The aim is to generate a candidate protein binder against this surface. Depending on its binding epitope and geometry, a binder could be investigated as a receptor modulator, a molecular recognition reagent, or a research tool for detecting/localising the receptor.

Possible therapeutic directions are hypotheses, not conclusions: receptor agonism or positive modulation may be explored in selected metabolic contexts, while receptor inhibition may be relevant to specific research or disease settings. INSR is also studied in cancer biology because insulin/IGF-related signalling can support tumour growth in some contexts. A binder against L1 cannot be assumed to be an agonist, antagonist, diagnostic reagent, or cancer treatment without dedicated experiments.

PDB 4ZXB is an X-ray structure of the human insulin receptor ectodomain in complex with four Fab molecules. The asymmetric unit contains five unique protein chains:

4. Installation and computational setup

4.1. Minimum system requirements

  • 64-bit Windows 10/11 system supported by Docker Desktop.
  • At least 8 GB system RAM for Docker Desktop; 16 GB RAM or more is recommended for this protein-design workflow.
  • Hardware virtualization enabled. Docker Desktop uses WSL 2 as its recommended Linux backend on Windows; follow its installer prompts if setup is needed.
  • An NVIDIA GPU is strongly recommended. RFdiffusion3 documentation recommends around 3 GB or more of GPU memory as a practical starting point; larger structures and batches may need more.
  • Enough free disk space for the Docker image, model weights, inputs and generated structures.

These are practical recommendations, not a guarantee that every design will run on every machine. Runtime and memory use depend on the structure, batch size and hardware.

4.2. Install Docker Desktop

Download and install Docker Desktop for Windows using the official guide below. During installation, choose the WSL 2 backend if the installer asks you to select one. On supported systems, Docker Desktop usually enables this backend by default.

Download and install Docker Desktop for Windows ↗

Do I need to connect Docker to WSL manually?

No separate PowerShell command is needed for this workshop. Docker Desktop manages its WSL 2 backend. Once Docker Desktop is open and shows that its engine is running, you can run the workshop's docker commands directly in Windows PowerShell. If the WSL 2 option was not selected during installation, open Docker Desktop → Settings → General and enable Use the WSL 2 based engine, then apply the change.

4.7. Create the RFdiffusion3 input JSON

Create a file named binder_design.json inside configs/. The JSON below is the configuration used in our tested run.

JSON · configs/binder_design.json
{
  "insulinr": {
    "dialect": 2,
    "infer_ori_strategy": "hotspots",
    "input": "/workspace/inputs/4zxb_cropped.pdb",
    "contig": "40-80,/0,E6-155",
    "length": "190-230",
    "select_hotspots": {
      "E64": "CD2,CZ",
      "E88": "CG,CZ",
      "E96": "CD1,CZ"
    },
    "is_non_loopy": true
  }
}

What does each setting mean?

  • insulinr: name of this design example. You may rename it, but keep the JSON structure valid.
  • dialect: 2: selects the input-specification format used by this workflow.
  • infer_ori_strategy: "hotspots": uses the selected hotspots to guide the binder orientation strategy.
  • input: path to the cropped PDB file inside the container. Keep this path unchanged when using the Docker command below.
  • contig: "40-80,/0,E6-155": asks for a new binder segment of 40–80 residues, separated from the fixed target by /0, followed by target chain E residues 6–155.
  • length: "190-230": allowed total length of the designed complex: 190–230 residues. This matches a 150-residue target plus a 40–80-residue binder.
  • select_hotspots: target residues and their selected atoms used as interface constraints.
  • is_non_loopy: true: requests a less loop-rich design preference. It does not force the whole binder to be helical.

5. Run RFdiffusion3

Run the following command from inside RFdiffusion_Project. It mounts the local project folder into the container and starts RFdiffusion3.

PowerShell · Tested RFdiffusion3 command
docker run --rm --gpus all `
  --mount "type=bind,source=$($PWD.Path),target=/workspace" `
  -w /workspace `
  rosettacommons/foundry:latest `
  rfd3 design `
  inputs=/workspace/configs/binder_design.json `
  out_dir=/workspace/outputs/insulinr_test `
  diffusion_batch_size=1 `
  n_batches=1 `
  low_memory_mode=True `
  prevalidate_inputs=True

Command explained

  • docker run: starts a new container.
  • --rm: removes the container after the run ends. Generated files remain in the mounted project folder.
  • --gpus all: makes available GPUs accessible to the container.
  • --mount ...: shares the current Windows project folder with the container at /workspace.
  • -w /workspace: sets the container's working directory.
  • rosettacommons/foundry:latest: selects the Foundry image.
  • rfd3 design: launches the RFdiffusion3 design workflow.
  • inputs=...: points to the JSON configuration inside the container.
  • out_dir=...: stores generated structures and metadata in the local outputs/insulinr_test folder.
  • diffusion_batch_size=1: generates one design sample per batch.
  • n_batches=1: runs one batch. Together, these settings request one design sample.
  • low_memory_mode=True: enables the memory-efficient mode used for our GPU-limited run.
  • prevalidate_inputs=True: checks the input specification before inference starts.
Hydra configuration note

Use the command exactly as shown. Do not add inference_mode=legacy to this workshop command: it was not accepted by the configuration in our tested container run.

6. Sequence design with ProteinMPNN

After selecting a suitable RFdiffusion3 backbone, ProteinMPNN can propose alternative amino-acid sequences compatible with that structure. For this project, the intended next step is to redesign the binder chain while keeping the insulin-receptor target chain fixed. This is a separate step and is not run by the RFdiffusion3 command above.

7. Structural validation and analysis

Backbone qualityCheck chain continuity, clashes and geometry.
Sequence plausibilityCompare sequence diversity and compatibility with the backbone.
Interface analysisInspect contacts, interface geometry and buried surface area.
Functional testingTest receptor binding and signalling experimentally before assigning agonist or antagonist activity.
Interpretation

A successful computational run produces candidate structures, not experimentally validated binders. Binding, receptor activation/inhibition and therapeutic relevance require separate experiments.
